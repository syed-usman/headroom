APFS CONTAINER FORENSICS

The "System Data" mystery, demystified.

Every Mac user has opened System Settings > General > Storage only to stare helplessly at a massive, opaque gray bar. Here is what macOS is actually storing under the hood:

🔒

1. Sealed System Volume (SSV)

~12.6 GB • Bit-for-bit immutable

macOS boots from a cryptographically signed APFS snapshot. The actual operating system files are completely read-only and sealed. They cannot grow, become fragmented, or get infected.

🚀

2. Cryptexes & Preboot

~9.0 GB • OS Security & Micro-updates

Rapid Security Responses and Safari updates live in dynamic "Cryptex" volumes so Apple doesn't have to rebuild the entire SSV snapshot on minor updates. Crucial for boot execution.

⚡

3. Dynamic VM Swap

~2 GB to 20 GB • Ephemeral RAM spillover

Apple Silicon's unified memory swaps dynamically into the APFS VM volume. It grows under heavy load and shrinks upon reboot. Not a leak, but vital scratchpad headroom.

💥

4. Runaway Developer Caches

Developer Caches & Artifacts • The Reclaimable Space

macOS lumps Docker raw disks, Xcode DerivedData, Ollama/HuggingFace model weights, Simulator runtimes, and Gradle jars into "System Data" because they live in ~/Library. This is what Headroom reclaims.

SAFETY FIRST ARCHITECTURE

Engineered for developers who can't afford broken builds.

Standard cleaners run reckless rm -rf on your project files. Headroom was built by engineers with three strict principles:

Rebuild Cost Metrics

Cleaning 20 GB of build caches might feel great until your next compilation takes 45 minutes and consumes your hotspot data. Headroom calculates compile time and redownload bandwidth before you clean.

7-Day Quarantine Undo

Accidentally cleaned an old client build configuration? Don't panic. Headroom isolates files into a local time-stamped quarantine directory. Restore them with one click or let them auto-expire.

Dual SwiftUI + CLI Engine

Use the luxury SwiftUI desktop application for visual workflows, or run headroom scan and headroom clean in automated terminal scripts, cron jobs, and CI environments.

Zero Sandboxing Compromises

Mac App Store apps are trapped in sandbox silos and cannot read developer directories or manage APFS snapshots. Headroom is distributed notarized with Full Disk Access transparency.
